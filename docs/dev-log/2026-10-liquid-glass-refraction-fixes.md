# 液态玻璃：位移发散、遮罩压掉效果、几何错位

日期：2026-10-22。起因是用户一句话：「修液态玻璃，这里面存在大量问题」。

---

## 一、现象

液态玻璃页（`gallery --route glass`）的折射「看起来没生效」：玻璃块盖在
深蓝底板上，看不出背景被弯过。参数面板的四个 `[−] [+]` 倒是点得动。

而**更早**的时候这一页还能看见效果（上一轮把折射从「强度 × 衰减」换成斯涅尔
定律之后），所以这一轮要查的是**为什么现在又不生效了**。

---

## 二、排查

### 2.1 先量「到底有没有东西可折射」

折射采样的是「**已经画在屏幕上**的东西」。于是先量几何（1400×800 画布）：

| 元素 | x | y | 宽 | 高 |
|---|---|---|---|---|
| `.glass-stage` | 288 | 264 | 732 | 255 |
| `.glass-backdrop`（三行说明文字） | 308 | 284 | **312** | 66 |
| `.glass-pane`（三块玻璃） | 308 / 544 / 780 | 373.6 | 220 | 120 |

**第三块玻璃（x=780..1000）下面什么都没有** —— 文字只到 x=620，剩下 380px 是
纯色底板。位移纯色等于没位移。

第二块玻璃也只压到 1/3 的字。**三块里有两块几乎没东西可弯。**

而 `.zstyle` 里那行 `translate-y: -102px` 的注释算式（「底板高度 = 89」、
「目标起点 = 191」）与实际布局**毫无关系** —— 实测底板高度是 66、玻璃块行的
起点是 350。那个 -102 是碰巧对的。

### 2.2 再看位移公式本身

`PSRefraction` 里的位移是

```hlsl
displacement = h * strength * (tan(slope) - tan(theta_r));
```

那是**薄棱镜近似**，只在**小角度**成立。而高度剖面 `h(t) = (1-(1-t)^4)^0.25`
在 `t → 0` 处**斜率发散**（这正是「光在边缘斜着进出」的数学表达），于是
`slope → 90°`、`tan(slope) → ∞`。

把同一条式子搬到 PowerShell 里逐点求值（`dt = 0.001`，与着色器同口径）：

| 参数 | 旧式（薄棱镜近似） | 新式（楔形偏折） | 契约（厚度） |
|---|---|---|---|
| 默认（28 / 26 / 1.50） | **491 px** | **13.2 px** | 28 px |
| 最大（80 / 48 / 2.00） | **2181 px** | 46.7 px | 80 px |
| 最小（4 / 2 / 1.05） | 110 px | 1.6 px | 4 px |

（采样步长 1000 → 100000 收敛到同一组数：旧式 491.3px、新式 13.24px。）

**旧式的位移比玻璃厚度大 17~27 倍。** 后果不是「看起来怪」，是玻璃边缘把
屏幕上几百像素外的内容拉进来 —— 而离屏外扩按 `thickness`（28px）算，
采样落在副本之外，被 `saturate` 夹到屏幕边上。

### 2.3 遮罩把效果乘掉了

`PSRefraction` 里有个遮罩 `mask = saturate(-d / edge)`，`edge` 那一版取的是
`min(half_size) * 0.5` —— 220×120 的玻璃块上就是 **30px**。

遮罩是**乘**在位移上的，而位移最大的地方恰好是 `d → 0`（边缘）—— 那一版遮罩
在边缘正好是 0。于是「最强的折射」被「最弱的遮罩」乘成 0。

实测**可见**位移（位移 × 遮罩）峰值只有 **~2px**；把遮罩收窄成 1px 的抗锯齿
带之后，同一处是 **~13px**。差 6 倍。

遮罩只需要挡住「元素外那一圈」，1px 的淡出足够 —— 它**不是**用来做渐变的。

### 2.4 倒角带宽度被圆角半径夹住

```hlsl
float bezel = min(max(i.color.g, 1.0), min(radius, min(half_size.x, half_size.y)));
```

`radius` 是玻璃块的圆角半径（12px），而倒角带宽的表到 48px。所以**倒角带
参数的上 3/4 是空档** —— 面板上「调大了没反应」。

物理上也不该这么夹：一块玻璃的边缘是「倒角平面 + 圆角」，倒角面（平的那一圈）
比圆角**宽**是正常的。真正的约束只是「倒角带不能宽过整个元素」。

### 2.5 core 侧的两条契约与着色器对不上

| 位置 | 写着 | 实际 |
|---|---|---|
| `Filter::is_identity` | 「厚度 0 但色散 > 0 ⇒ 非恒等」 | 色散**乘的是位移**，位移是 0 ⇒ 恒等。后果：厚度 0 那一档照样开离屏 pass、照样拷一份**全屏**目标副本，而画面一个字都不变 |
| `Filter::outsets` | 「折射要往元素外多读 `strength` 那么多像素，所以离屏矩形必须留出这一圈」 | 折射采样的是 `g_dst`（**全屏**副本），离屏 RT 在折射路径上**根本没人采样**。外扩只是把 RT 撑大；而且拿不到副本降级成普通合成时，外扩会让元素自己的内容**多画一圈**到元素外面 |

两处都写着**看起来很有道理**的推理，而两条推理的对象搞错了。

## 三、排除的假设

- **「着色器没重编，GPU 上跑的还是旧版本」** —— 排除。用 `fxc` 重新编一遍
  `PSRefraction`，与已提交的 `.bin` **逐字节相同**（SHA256 一致）。GPU 跑的
  就是当前源码。（但 `.bin` 的 mtime 比 `.hlsl` 旧 ⇒ `shader_assets_are_in_sync`
  那条门禁是红的 —— 那是**时间戳**问题，不是内容问题，见第五节。）
- **「是 GPU 设备死了所以画面冻住」** —— 排除。本机 `D3D12CreateDevice` 确实
  失败（`0x887A0006`，上一轮的 dev-log 已记），但那是**整幅画面**冻住，
  而这里量的是**布局几何**（纯 CPU，不碰 GPU）。
- **「`translate-y` 没生效」** —— 排除。`translate-y` 是**绘制期**位移
  （`paint.rs`），布局矩形不含它。实测玻璃块绘制位置 271.6..391.6，与文字
  284..350 重叠 66px —— 视觉上确实压上了，只是压的是**只有 312px 宽**的文字。
- **「玻璃块的位置算错了」** —— 排除。布局矩形与绘制位置都对，问题是**下面
  没有足够宽的内容**。
- **「三块玻璃参数不一致是 bug」** —— 排除（但**标题**是 bug，见第四节）。

## 四、结论：改了九处

### 着色器（`zephyra.hlsl`，D3D11 / D3D12 两份逐字节相同，一起改）

1. **位移式**换成像限的楔形偏折 `δ = h · strength · sin(Δ) / cos(Θr)`。
   它在 `Θs → 90°` 时趋于 `h` 而不是 ∞，且**恒有 δ ≤ thickness** ——
   「位移不超过厚度」这条契约**由公式本身保证**，而不是靠外扩去追。
   `IOR = 1 ⇒ Δ = 0 ⇒ δ = 0`（不折射）这条性质仍然成立。
2. **遮罩**从 `min(half_size) * 0.5` 收窄成 1px 的抗锯齿带。可见位移峰值
   从 ~2px 变成 ~13px。
3. **倒角带**不再按圆角半径夹，只按半边长夹。倒角参数的上 3/4 不再是空档。

### core（`zephyra-core/src/filter.rs`）

4. `is_identity`：`strength == 0` ⇒ 恒等（色散乘的是位移）。
5. `outsets`：折射**不外扩**（采样对象是全屏副本，不是离屏 RT）。
6. 新增 `filter::refraction`（`glass_surface_height` / `displacement` /
   `max_displacement`）—— 位移公式的**纯 Rust 镜像**，只用来**验**契约。
   着色器改了式子，这里必须同步改，门禁会红。

### 画廊页面（`gallery/src/app/pages/effects.rs` + `styles/pages.zstyle`）

7. **竖条带**：加了一排贯穿整个舞台的竖条（`27 × 20 + 8 × 19 = 692` = 舞台
   内容宽，正好铺满）。三块玻璃下面**都有**可弯的东西了。竖条比文字更合适：
   位移是十几像素量级，15px 的细笔画弯起来看不清，27px 的竖条边缘一弯就看得见。
8. **三块玻璃的厚度真的不同**了（档位偏移 ∓4）。早先三块用的是**完全相同**的
   滤镜，标题却写着 Thin / Normal / Thick —— 标题在**说谎**。现在标题名副其实，
   而面板仍然**共用**一组参数（拖一次三块一起变）。
9. **标签移到玻璃下面**，`.glass-panes` 的 `translate-y` 于是恰好等于**竖条带的
   高度**（-120px，一个整数）。标签在**上面**时，位移量得再减去标签高度，
   而标签高度取决于**字体度量** —— 换个字体那个数就错位了，而错位的症状是
   「玻璃块没压在竖条上」（画面上等于没有折射）。

顺带删掉一节**遗留**：液态玻璃页上有一节标题写着「Filters」、内容却是**两个
进度条** —— 那是旧「效果页」（这一页以前叫 effects）的残留，与液态玻璃无关。
对应的两个文案键（`ui.filters` / `ui.progress`）也随之成了死条目，一并删掉。

## 五、门禁

| 门禁 | 钉住什么 |
|---|---|
| `zephyra-core` `refraction_displacement_is_bounded_by_the_thickness` | 位移峰值 **≤ 厚度**（默认档 13.24px ≤ 28px）；同时断「恒等于 0」（公式退化了） |
| `zephyra-core` `refraction_with_ior_one_has_no_displacement` | `IOR = 1` ⇒ 位移是**亚像素**的（实测 ≤ 0.0025px，判据 0.01px） |
| `zephyra-core` `refraction_without_thickness_is_the_identity` | 厚度 0 ⇒ 恒等（**色散也不例外**）；而 `IOR = 1`（厚度正常）**不是**恒等 —— 那是诊断位，pass 必须真的跑 |
| `zephyra-core` `refraction_does_not_grow_the_offscreen_rect` | 离屏矩形 == 元素矩形 |
| `zephyra-fx` `dispersion_alone_cannot_survive_without_strength` | 厚�� 0 ⇒ 不产出离屏 pass |
| `zephyra-fx` `refraction_does_not_grow_the_offscreen_rect` | 同上（在 fx 侧断后果） |
| `gallery` `glass_panes_cover_the_refraction_target` | 玻璃块**画出来的**位置盖住竖条带；竖条铺满舞台内容宽；竖条够宽（位移才看得见） |
| `gallery` `glass_params_are_not_hard_coded` | 改过的（原判「三块参数完全相同」） | 倒角带宽 / 色散 / 折射率三块**逐项相同**，而**厚度不同且有序** |

**两条既有门禁被改判据**（它们原先钉的是**错**的契约）：

- `zephyra-fx` `dispersion_alone_is_still_an_effect` —— 原判「厚度 0 + 色散 > 0
  ⇒ 非恒等」。理由（色散不依赖位移）与着色器不符。改名
  `dispersion_alone_cannot_survive_without_strength`，改判「恒等」。
- `zephyra-fx` `refraction_outsets_by_strength_in_pixels` —— 原判「折射外扩 =
  强度」。理由（折射要往元素外多读那么多像素）把采样对象搞错了。改名
  `refraction_does_not_grow_the_offscreen_rect`，改判「不外扩」。

（另：`zephyra-platform-win` 的 `flags_are_pinned` 上一轮已经改过一次判据 ——
那一轮的 `MUI_LANGUAGE_NAME` 恰好也是**钉着 bug** 的门禁。本仓这种「门禁把
bug 钉住」的形状不少见：**门禁只能钉住它当时理解的那个契约**，而那个理解可能
是错的。）

## 六、顺带修好的一条既有门禁

`zephyra-winit` 的 `shader_assets_are_in_sync`（D3D11 那份）本轮之前是**红**的：
它比的是每个 `.bin` 的 mtime 晚于 `.hlsl`，而 `.hlsl`（10-18）比 `.bin`
（10-11）新。

实测 `.bin` 的**内容**与源码是一致的（重新编一遍，SHA256 逐字节相同）——
所以那是**纯时间戳**问题（检出把 `.hlsl` 的 mtime 刷新了）。

本轮改了 `.hlsl`，于是**必须**重编全部 20 个 `.bin`（两个 crate 各一份）——
重编完这条门禁自然转绿。这不是「顺手修了个无关的失败」，而是改着色器的
**必要步骤**。

## 七、第二轮：改完之后「一点液态玻璃的形状都没有了」

用户反馈：问题**更严重**了 —— 玻璃块**一点形状都没有**。

这一轮查出来的**不是**新问题，而是**上一轮引入的问题** + 一条**早就存在、
但被上一轮的设计盖住**的问题。

### 7.1 白 @ 30% 的玻璃压**白**竖条 ⇒ 玻璃块整个消失

上一轮加的折射输入是一排**白色**竖条（`#ffffff` / `#6ea8ff`）。而玻璃块的底色
是**白 @ 30%**（`#ffffff4d`）。

**白 @ 30% 压在白上还是白** —— 玻璃块在白竖条上**完全看不见**（逐像素相同）。
竖条占舞台内容宽的 77%（27/35），于是玻璃块**大半的面积**「消失」，
只剩下缝隙与另一种颜色的竖条上还看得出边界。

症状与「折射没接上」**长得一样**（都是「看不出玻璃」），而排查方向完全相反：
一个在几何与配色，一个在着色器。所以这一轮的判据必须断**「看得见」**。

**修法**：竖条取**中间调**（`#2f6fb5` / `#1d7a72`）。白 @ 30% 压在中间调上
会明显提亮（实测 `#2f6fb5` 从 (47,111,181) 变成 (174,203,230)），
于是玻璃块在竖条上读作一层「磨砂」—— 那正是液态玻璃该有的样子。

描边也一并提亮（`#ffffff66` → `#ffffffb3`）：玻璃块的**形状**主要靠这一圈
亮线读出来，底色负责「里面是磨砂的」，两者分工。

### 7.2 顺带查出：CPU 参考光栅器把 alpha 用了**两次**

查上面那条的时候，**像素对不上**：白 @ 30% 压在白竖条上，参考图给的是
**229** 而不是 255（白叠白必须是白）。

顺着查下去发现：`zephyra-fx` 的 CPU 光栅器在混合时写的是

```text
dst = src·a + dst·(1 − a)
```

而**顶点色在 `quad::expand` 里已经预乘过 alpha**（`quad::tests::
vertex_color_is_premultiplied` 钉着这条不变量）—— 于是 alpha ��了两次
（一次在预乘里，一次在混合里）。

**正确**的式子（预乘源 + `ONE/INV_SRC_ALPHA`）是

```text
dst = src + dst·(1 − src.a)
```

**后果**：参考图里**每一个半透明元素**都比它该有的暗一截。实测白 @ 30%
压白：双重预乘给 229（线性 201 → sRGB 229），正确值是 255。
参考图是本仓**唯一**的像素级自验手段 —— 它整体偏暗这件事，此前没人发现。

顺带把 `coverage` 的位置也理清了：覆盖率是**覆盖率**，它同时缩放源色与源
alpha；而顶点色里的 alpha 是图元自己的不透明度，两者不能混。

### 7.3 新门禁：玻璃块必须**真的**盖住东西

`the_glass_block_is_distinguishable_from_what_it_covers`（gallery）——
**渲染两遍**（一遍正常、一遍把 `.glass-pane` 的底色改成全透明），比**同一处**
像素的差别。

为什么不用「玻璃块内 vs 玻璃块外」那种比法：三块玻璃**紧挨着**排满整个
竖条带（3 × 220 + 2 × 16 = 692 = 舞台内容宽），**块外没有同段图案**可比 ——
拿缝隙那 16px 去比，量到的是「一块亮条 vs 一块暗条」，与玻璃无关。

判据取**面积占比**而不是平均差（平均差会被「只有一小块变了」稀释）：
**玻璃底色必须影响玻璃块内 90% 以上的像素**。实测白竖条时只剩 **64.5%**
（只有另一种颜色的竖条与缝隙变了）⇒ 门禁红；中间调竖条时 ≈ 100% ⇒ 绿。

## 八、第三轮：「根本不像真玻璃，一点透明度都没有」

用户反馈（配真 GPU 截图）：玻璃块读作**贴在图案上的不透明贴片**。这一轮动了
三处——透明度、图案几何、默认参数——**缺一个症状就回来**，所以拆开记。

### 8.1 透明度：白 @ 30% 的纱太厚

`.glass-pane` 底色 `#ffffff4d`（白 @ 30%）把下面的图案洗掉一截，截图上的观感
就是「不透明」。改 `#ffffff26`（15%）：提亮仍读得出来（`#2f6fb5` 上有可测的线性
差，像素门禁阈值 0.02 仍留数倍余量），图案不再被洗白。玻璃的**形状**本来就不靠
底色——靠描边那圈亮线（`#ffffffb3`）。

⚠ 像素门禁 `the_glass_block_is_distinguishable_from_what_it_covers` 里 patch 的
那串 `#ffffff4d` 必须跟着改：它是「把玻璃底色替换成全透明」的替换串，对不上就
**静默不改**、两遍渲染相同、门禁假绿。

### 8.2 图案几何：竖条 → 20×8 棋盘格（根因）

逐像素取样先**排除**了「折射没算」：玻璃外 x=586..593 是深色缝隙、玻璃内同一段
变成了青条——位移确实在把 8px 外的内容拉进来。看不出来的原因在图案：

1. **竖条在竖直方向处处相同**，而玻璃上下边的位移正是**竖直**的——上下边占边缘
   总长的三分之二（220+220 对 120+120），那三分之二**天生不可见**；
2. 剩下三分之一（左右边）也只在条与条的边界上显形，而按默认档算的峰值位移
   （13px）比条宽（27px）小——多数像素位移完还停在同一根条里。

切成棋盘（20 列 × 8 行，列 27px、行 25px）后两个轴上**都有**边界可撞。行高 25
不是随手取的：`200 / 8 = 25`，横边界落在 25/50/…/175，而玻璃画在条带 40..160 ——
上下边界**各往内 10px**（在位移可达范围内），且露区 0..40 与 160..200 里**各有**
一条横线（25、175）当玻璃外的对照。40px 与 20px 行都会让边界正好压在 40/160
（玻璃上下边）上，位移把边界推出玻璃外，反而看不见。

带高 120 → 200、`.glass-panes` 的 `translate-y` −120 → −160、`.glass-stage`
370 → 450：**玻璃外必须有同一段图案**（上一版带与玻璃同高 ⇒ 玻璃把整条带盖满
⇒「贴片」观感的另一半原因）。

⚠ `.glass-bar` 少了 `cross-align: stretch` 时，段 `.glass-seg` 量成 **0 宽**而
`height`/`y` 都正常——画面上棋盘静默塌成纯竖条，只看边界的断言照常绿。新门禁连
宽度一起断（去掉那条样式复现过、门禁当场红）。

### 8.3 默认参数：28 / 26 → 48 / 40（厚度与倒角带必须一起动）

按 `PSRefraction` 的式子代入算：默认档 28/26 时峰值位移 13px，但在**距边 1px**
内就爬到峰值、13px 处衰减到 1px 量级——弯折被塞进一条 1~3px 的窄缝，观感是
「格子少了一根」而不是「被掰弯」。`t = -d/bezel`：倒角带宽直接决定弯折在屏幕上
铺开多少像素。两个一起抬到 48 / 40：峰值 ~23px、铺开 ~20px；三块玻璃（±4 档 =
±16px 厚度）峰值约 **14 / 23 / 34px**，「薄 / 普通 / 厚」才名副其实。

只抬厚度 → 位移更狠但仍塞在窄缝里（接缝更刺眼，不是弯曲）；只抬倒角带 → 铺开
变宽却没有幅度。

### 8.4 排除的假设

- **「折射没接上 / 着色器没跑」**：逐像素取样证伪（见 8.2）。
- **「厚度调大就够了」**：见 8.3——两个参数互为一半，缺一不成弯折。
- **「倒角带超过圆角半径（12px）是白调」**：着色器夹的是
  `min(bezel, half_size.x, half_size.y)`（110 / 60），**不是**半径。`glass.rs`
  里那句老注释是「按半径夹」那版留下的，已改——真照它调就会把默认档调回 12px，
  正是「贴片」复发的路子。
- **「行高取 40 / 20 让边界更多」**：那两种行高让边界压在玻璃上下边上（8.2）。
- **「标签挪出图案区」**：标签落在条带 y 168..184，与玻璃（40..160）的相对位置
  算下来**必然**压在图案上——只能改颜色（`#ffffffcc`），挪不动。
- **「顺手改 HLSL 注释就行」**：改完 `shader_assets_are_in_sync` 当场红——那条
  门禁按 **mtime** 卡 `zephyra.hlsl` 与 20 个 `.bin` 的新旧，注释也算改动。处置是
  **还原**（内容已回到 HEAD，把 mtime 恢复成编译时刻），而不是为一句注释 churn
  20 个二进制。代价记在「未做」里。

### 8.5 门禁（gallery：新增 2 条、改 1 条）

- `refraction_target_extends_beyond_the_glass`：带子必须比玻璃**高一截**（上下各
  ≥30px 露出）——玻璃外没有同段图案就无从对照（8.2 的贴片根因）。
- `refraction_target_has_structure_within_reach_of_both_pane_edges`：玻璃上下边
  往内 **20px** 内必须有横边界（REACH=20：按新默认档的剖面解出可达 ≈23px，留
  3px 余量；旧默认档是 12px）——**连列宽与段宽一起断**（0 宽段塌陷见 8.2）。
- `glass_panes_cover_the_refraction_target` 改判据：玻璃块必须**整块落进带内**
  （原判据只要求「压住」，探出带外照样绿，而探出部分底下没东西可折射）。
- 像素门禁 patch 串 `#ffffff4d` → `#ffffff26`（8.1）。本轮后该门禁已被第四轮
  删除（9.2），这条记的是第三轮当时的动作。

## 九、第四轮：玻璃不许有底色（纯折射表达层级）

需求（用户原话）：「玻璃要是透明的，不要有底色，纯靠折射反应层级关系」。

前三轮都在调那层纱（30% → 15%），这条需求把方向整个反过来：**不加**才是对的。
`.glass-pane` 的 `background: #ffffff26` 被整个删掉 —— 玻璃现在只剩
几何（宽/高/圆角）+ 描边亮线 + `props::FILTER` 上的折射链。

### 9.1 管线为什么不会因此断掉

担心过「没有 `background` 就没有 quad ⇒ 滤镜链无处可挂 ⇒ 玻璃整个消失」。
证伪依据是 `zephyra-core/src/paint.rs` 的 quad 发射条件：

```rust
if fill.a > 0.0 || has_stroke { /* 发 Command::Quad，filter 挂在这条命令上 */ }
```

玻璃块有描边（`#ffffffb3`，1px）⇒ quad 照发、filter 照挂、离屏 + 折射照跑。
合成阶段画的是**被扰动的背景**（`PSRefraction` 采的是屏幕，不是离屏内容），
`redraw_original` 之后描边画回最上层 —— 画面 = 位移后的图案 + 一圈亮边。

真 GPU 截图（v8）逐条对上：玻璃内外的格子亮度逐格相同（无任何纱）、边缘弯折
与色散（厚玻璃右缘的红/蓝色边）都在、描边圈出形状。

### 9.2 删掉的像素门禁，与它的替代

`the_glass_block_is_distinguishable_from_what_it_covers`（第二轮加的）被删。
它的前提是「底色必须影响画面 ≥90% 的像素」，而这条需求恰恰要求**相反**的事
（玻璃必须**不**影响画面）—— 判据整个反转，留着只会恒红。

反过来的「玻璃不改变画面」也做不成像素门禁：

- CPU 光栅（`zephyra_fx::cpu_only`）**不实现滤镜** —— 玻璃在那条路上本来就
  只剩描边；两遍渲染的唯一差别只可能是一个 alpha 混合，而「有底色的那一遍」
  已经不存在了；
- 唯一还能构造的对照是把玻璃块藏起来（宽/高改 0），但那会把标签挪进对照区
  （标签在玻璃块下方 8px，块一塌标签就顶上去），逐像素比对必然红在标签上。

替代门禁 `the_glass_pane_has_no_fill`（字符串级）：

- `Container.glass-pane` 规则体内不许出现 `background`；
- `#ffffff26` / `#ffffff4d`（两代白纱）不许再出现在任何样式表里。

判据先剥掉 `/* … */` 注释再找规则 —— 规则上方的注释讨论的就是「为什么不许有
background」，不剥的话注释里的字样会被当成规则文本。门禁会咬：把
`background: #ffffff26;` 加回去复现过，当场红。

「看得见玻璃」（位移本身）由三条几何门禁 + 着色器侧门禁钉住，观感由真 GPU
截图复核（v8：弯折与色散清晰可辨）。

### 9.3 排除的假设

- **「去掉底色 ⇒ 玻璃消失（没有 quad 可画）」**：见 9.1，描边满足发射条件。
- **「白格子现在可以用了」**：不行 —— 玻璃的形状下限现在是那圈 70% 白的
  描边亮线，白格子上白描边等于没描边；浅色标签压白格也读不出来。
  `.glass-bar` 注释里的理由已改成这两条 + 对比度。
- **「用像素门禁钉『零底色』」**：见 9.2 的两条排除。

## 十一、未做

- **Vulkan**：滤镜管线仍未接通（那边 `fs_blur_h` / `fs_composite` 没被调用），
  所以 Linux 上这一页与「没设滤镜」无异。
- **D3D11 的折射像素门禁**：与 D3D12 共用同一份 HLSL 与顶点数据，两条真机门禁
  的内容会重复。上一轮已记。
- **液态玻璃的四层外观装饰**（镜面高光 / 内阴影 / 内边缘亮线 / 玻璃外投影）：
  仍未做。前两轮修的是**位移**，第三轮修的是**纱、图案几何、默认参数**——那四层
  一层没碰。其中镜面高光卡在数据模型上：`PropertyValue` 没有渐变，高光要有
  **可插值的亮斑**就只能拆成多个色块子元素，效果与代价都还没评估。
- **折射路径上多画的那一趟离屏内容**：折射的离屏 RT 里装的是元素自己的内容，
  而 `PSRefraction` **不采它**（元素的内容是之后由 `redraw_original` 画回屏幕
  的）—— 所以那一趟是**白画的**。删掉它要动渲染器的状态机（`absorb` 记账、
  `unimplemented_filters` 的加减都在那一段），风险大于收益，本轮不动。
- **`zephyra.hlsl` 注释里的「默认参数 thickness=28 / bezel=26」已过期**（默认档
  现为 48 / 40，见 8.3）。改这行注释也会让 `shader_assets_are_in_sync` 按 mtime
  变红，得把 20 个 `.bin` 一起用 fxc 重编——为一句话 churn 20 个二进制不值，
  第三轮选择**还原**。等下次真正改着色器逻辑时顺手改这一句。
