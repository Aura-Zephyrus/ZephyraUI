# 2026-10-31 `.zypui` 写法统一（排版门禁）

> 现象：三份 `.zypui` 各写各的排版 —— class 41 处不在行尾、11 个开始标签跨行、
> 18 处 `<if><X/></if>` 挤在一行；「统一写法」既没有规范文件也没有机器判据，
> 改完同样没有东西保证不漂回来。

## 排查

先量分布再定方向（`.zypui` 全是 LF，按 `\n` 分行、剥掉 `<!-- … -->` 后统计）：

| 写法分歧 | 存量 | 改哪边代价小 |
|---|---|---|
| `class` 位置 | 185 个 `key`+`class` 元素里 **162** 个已在行尾（87.6%），23 个不在；另有 18 个**无 key** 元素的 class 也不在行尾 | 全部挪到行尾：**41** 处；反过来要挪 **89** 处 |
| 开始标签跨行 | 11 处（`shell.zypui` 的 `TextLabel` / `NavItem` / `control`） | 全部收成一行 |
| 一行两个元素 | 18 处（`<if cond="…"><PageX/></if>`） | 全部展开成三行 |

**先确认属性顺序是不是语义**：`zypuic` 的 `XEl::attr` 按名字取、`encode.rs` 按
名字写表，07 的验收一节也写明「属性按名字取用，插入顺序不是语义，对照时按键名
排序」⇒ 归一化只动排版，编译产物逐字节不变。

于是写了一个一次性归一化脚本（合并跨行标签 → 展开挤一行的元素 → `class` 移到
行尾），跑在三份文件上；判据**不看 diff 好不好看**，而是看**与改动前语义等价**：
剥注释后取「属性 `name="value"` 多重集」「标签多重集」「注释条数」与改动前逐一
比对（`controls` 642 / 484 / 19，`shell` 839 / 651 / 14，`demo` 71 / 48 / 8，
三份全等）。

规范写进 `docs/developer/zypui-style.md`，门禁放进 `.zypui` 的编译器 `zypuic`
（而不是应用侧）：扫工作区**全部** `*.zypui`（递归，跳过 `target` / `.git`），
五条规则，输出 `路径:行: 规则N + 原文`。

## 排除的假设

1. **「排版脚本改完就是对的」** —— 第一版合并跨行标签的循环多推进了一行：标签
   合并后 `$i` 已指向下一个未消费的行，末尾又 `$i++` 一次，于是**每个跨行标签
   吞掉了紧跟其后的那个元素**（`shell.zypui` 的 `<DemoRow>` / `<Section>` 开标签
   当场消失）。靠上面那条多重集比对当场抓到，回滚改判据（合并分支不再推进）后
   重跑。**排版类改动必须有「与改动前语义等价」的机器对照**，否则 `git diff`
   看着正常、树已经少了一截。

2. **「门禁第一版把 class 违规都报出来了」** —— 它只报 23 / 41。`attr_names`
   遇到带缩进的行时，取「标签名之后的第一个空白」只吃掉**一个**空白字符，余下的
   空白让标签名与第一个属性粘成 `<control class`，于是 `class` / `key` 从属性表里
   凭空消失 —— 无 key 的 `<control class="…" interactive="…">` 因此一条都报不出来，
   `key` 不在首位的检查更是对所有带缩进的行形同虚设。抓到它的办法是**拿归一化前
   的内容回跑门禁**（反向对照：红的数量应当正好等于手数出来的违规数），并在判据
   自检里补两条**带缩进**的回归样例。

3. **「删掉注释再逐行检查，行号还对得上」** —— 直接删除注释会连带删掉注释里的
   换行，行号整体前移、报出来的行号指向错误的行；而且多行注释的续行是按 `<!--`
   对齐的（5 空格），删完还会留下一个只有缩进的空行，被当成「行尾有空白」的违规。
   改成**打码**：注释区的字节除换行外全换成空格，字节数与换行数与原文相等 ⇒ 行号
   恒等于源文件行号，注释里的 `<` 也不再可能算成标签。

4. **「PowerShell 的 `Get-Content` 可以用来数行」** —— 它把本仓 UTF-8（无 BOM）
   的 `.zstyle`/`.zypui` 按 ANSI 解码（中文出乱码），**行数也对不上**：
   `demo.zypui` 实测 `Get-Content` 72 行 / `File.ReadAllLines` 与 Rust `lines()`
   83 行。前几轮统计（含「41 处 class 不在行尾」这个数）就是拿它算的，行号整体
   偏移 —— 差点照着假行号去改文件。真因没查（判据只需要「别用它」），后来一律用
   .NET `File.ReadAllText`（默认 UTF-8）或直接信 Rust 门禁自己报的数。

## 结论

- 三份 `.zypui` 归一化到统一写法：一个开始标签一行、一行一个元素、
  `key` → 内容 → 行为/结构 → `class` 收尾、缩进 2 空格、非空行以 `<` 开头。
- 门禁报违规从 **90**（跨行续行 20 + 跨行标签 11 + 一行两元素 18 +
  class 不在末尾 41）降到 **0**；`key` 不在首位本来就是 **0**（存量一直合规）。
- 规范成文 `docs/developer/zypui-style.md`，并在 `07-declarative-ui.md` /
  `docs/developer/README.md` 挂了入口。
- 与语义的边界写进规范：**class 的词序是语义**（类序即匹配序，一个词不许动），
  class 的**位置**不是。
