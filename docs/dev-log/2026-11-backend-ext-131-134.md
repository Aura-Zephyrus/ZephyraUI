## 本轮已做（可验证）

- ext-wgpu：修复 `zephyra_render_ext::types` 导入、wgpu 24 `Backend` 映射（移除 `Dx11`）、增加 `facade/native/native-dx12` features 与可选依赖骨架；`native` 模块按 feature 暴露。默认依赖仍包含 `wgpu = "24"`，完整编译取决于依赖缓存/网络。

## 排除的假设

- **“CPU ext upload 一定要独立提交/单独 fence”**：当前实现把上传记录进同一帧命令列表并把 staging 保存在 `ExtResource` 中，保证 GPU 执行前不释放。它不是最优池化方案，但满足“命令路径可用”闭环；fence 回收/池化需后续按 §15.4/帧生命周期优化。
- **“ext SRV 槽位可与动态 `upload_texture` 任意交错且永不冲突”**：当前使用 `next_texture_slot` 单调分配并跳过 DST 保留槽；这对现有路径可用，但未实现完整空闲槽回收/纹理生命周期绑定。需要后续与 `TextureTable`/卸载路径统一。
- **“wgpu-hal 原生导出 API 在所有 24.x patch 下完全一致”**：`zephyra-ext-wgpu` native 路径是 feature-gated 接线点；签名/类型随 `wgpu`/`wgpu-hal` 细版本变化时应按实际 API 调整。
- **“无 Vulkan external-memory 扩展也能完成真实 dmabuf/external VkImage 导入”**：`zephyra-vulkan` 当前未启用 external memory 扩展；真实跨进程/跨设备导入需要 `VK_KHR_external_memory*` / 平台 fd/win32 handle 导入路径与资源创建标志，不能仅凭 `RawHandle` 元数据完成。

## 结论与 §15 决策占位（需实测后定稿）

### §15.1 NT Handle 安全属性（131）
- **建议默认**：导出侧使用显式 `SECURITY_ATTRIBUTES`，`bInheritHandle=false`；生产默认不使用 null DACL。跨进程同用户共享优先使用受限 DACL/命名对象策略；需要更宽松共享时由调用方显式 opt-in。
- **当前实现**：`zephyra-ext-wgpu` native-dx12 导出路径已构造 `SECURITY_ATTRIBUTES` 骨架；仍需按目标安全模型补充 DACL（不在无实测策略下硬编码宽松权限）。

### §15.2 Vulkan 黑名单（134）
- **占位**：按 adapter/driver/vendor/device + ICD 版本记录导入失败；首次失败降级 CPU/禁用零拷贝并写 dev-log。黑名单判据必须来自实测（驱动/ICD/扩展组合），不能仅凭 vendor 猜测。

### §15.3 CPU fallback 阈值（134）
- **占位**：以帧预算（如 8.3ms@120Hz / 16.6ms@60Hz）和纹理尺寸/频率为输入；采集 `upload bytes/frame`、staging 拷贝耗时、GPU copy/fence 等待后再定默认阈值。当前实现保留 `ImportError::is_retryable`/fallback 路径，但无全局吞吐阈值策略。

### §15.4 多窗口共享纹理池（134）
- **占位**：`resource_key` 全局命名空间已由契约要求；共享池需定义 owner window/context、引用计数、SRV/descriptor 生命周期、窗口销毁时的延迟释放与 fence 安全点。D3D12 当前 `sync_ext_texture_srvs`/staging 保活策略需在多窗口与高频替换下复测。

### §15.5 Hook panic（133/已部分实现）
- 后端 Custom dispatch 已用 `catch_unwind(AssertUnwindSafe)` 隔离 ext/internal hook；panic 通过 `zephyra_ext::debug::log_hook` 记录（debug 开关）。Release/生产策略（计数、禁用失效 hook、上报）需补充运行时策略与测试桩。

## Vulkan Windows 可运行性（本轮补充：ash/zephyra-vulkan）

### 现象

`zephyra-vulkan` 原为 Linux/Wayland 路径（`VK_KHR_wayland_surface`、`zephyra-platform-linux`、winit Wayland handle），在 Windows + Vulkan loader/ICD 可用环境无法创建 surface/运行 demo。

### 排查与实现

- 平台分支：`Cargo.toml` 改为 `target_os=linux` 依赖 `zephyra-platform-linux`，`windows` 依赖 `zephyra-platform-win`。
- Surface：按平台启用 `VK_KHR_win32_surface` / `VK_KHR_wayland_surface`；`Device` 持有对应 ash extension；`Surface::new` 在 Windows 通过 raw-window-handle 提取 `HWND/HINSTANCE`（`GetModuleHandleW(NULL)` 兜底）创建 Win32 surface。
- Host：`zephyra_platform_linux::current()` 改为 `platform_current()` cfg 分发；`window_handle_of` 支持 Win32。
- Demo 接线：`examples/demo.rs` 的 `linux-vk`（ash Vulkan）cfg 从 `not(windows)` 扩展为可在 Windows 生效（且不与 Windows D3D12 默认路径冲突），使 `cargo run -p zephyra-foundation --bin demo --no-default-features --features linux-vk` 可走 Vulkan 后端。

### 排除的假设

- **“有 Vulkan loader/`vulkaninfo` 就等于现有 ash 后端可跑”**：不成立。实例扩展、平台 surface、句柄来源、宿主平台依赖、demo cfg gate 都是 Linux/Wayland 形态，必须逐项适配。
- **“`vkCreateSwapchainKHR` 的 `HOST_MEMORY_ALLOCATION_FAILED` 一定是内存不足”**：本机实测是 `VkSurfaceCapabilitiesKHR` 返回异常 extent（如 `2789952688x362`、`current/min/max` 同值），导致 swapchain 请求异常尺寸。修复为：extent 异常时回落 `window.inner_size()`；对 min/max/extent 做 16384 上限与 clamp 保护，并输出 warning。根因仍需结合具体 ICD/驱动/ash 查询路径复核（可能是能力查询/结构解释在特定路径上的兼容问题），当前以“可运行 + 可诊断”优先。
- **“`ZEPHYRA_VK_DEBUG=1` 只要请求校验层即可”**：本机无 `VK_LAYER_KHRONOS_validation`。实现改为探测 layer、缺失时 warning 并继续；若启用失败则重试不带 validation layer 的 instance 创建，debug utils messenger 仍可在 `debug_on` 下尝试。

## 131 D3D12 完善（本轮补充，2026-11-08）

### 实现

- **ext SRV 槽位 fence 安全回收**：`zephyra-winit-d3d12` 的 `begin_frame()` 执行全量 `wait_gpu()`，`Renderer::sync_ext_texture_srvs()` 在其后录制；因此 `sync_ext_texture_srvs` 开始时 GPU 空闲，回收的 ext SRV 槽位可安全复用。`alloc_srv_slot()` 恢复从 `free_texture_slots` 复用，并补充“若改为 ring-buffer/多帧在飞则必须改为 fence 值延迟回收”的约束注释。`ext_srv_keys` 账本继续跟踪 ext key→slot。
- **CPU ext staging / 资源 fence 安全退役**：`ExtPool` 增加 `retired: Vec<ExtResource>`；`remove/insert(replace)` 不再立即 drop 旧 `ExtResource`（含 `staging`、`ID3D12Resource`、SRV 元数据），而是移入 `retired`。`Renderer::sync_ext_texture_srvs()` 在 GPU 空闲点调用 `ExtPool::release_retired()` 释放退役资源，避免上传 staging/资源在命令列表可能仍引用时被释放。**池化**（按 size bucket 复用 staging buffer）未在本轮实现；当前优先保证 fence/生命周期安全。
- **§15.1 NT DACL/opt-in 策略**（`zephyra-ext-wgpu` `native-dx12`）：`export_nt_handle_source` 默认不传显式 `SECURITY_ATTRIBUTES`，避免 null DACL；新增 `NtHandleExportPolicy` + `export_nt_handle_source_with_policy`，仅在调用方显式 opt-in 时传入安全描述符/继承策略，调用方负责提供符合生产安全模型的 DACL。

### 排除的假设

- **“全量 `wait_gpu()` 下 SRV 槽位永远不能复用”**：不成立。全量等待后无在飞命令引用旧 descriptor，可复用；但该结论与当前同步模型绑定，改 ring-buffer 后必须失效。
- **“ext unregister/replace 时直接 drop staging 是安全的”**：不成立。unregister 可发生在帧提交后/下一次等待前；staging 必须按 GPU 完成点退役。

### 剩余

- CPU ext staging buffer **池化**（size bucket 复用）可在确认 fence 安全退役后按 §15.4/吞吐实测补充。
- 若 D3D12 帧模型从全量 `wait_gpu()` 演进为多帧 fence ring，SRV 退役与 staging 退役需统一改为 per-fence-value 延迟释放。
