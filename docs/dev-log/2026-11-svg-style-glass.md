# SVG 式像素偏移玻璃：把「用玻璃的成本」从 8.4 ms/帧压到 ~0

> 现象：gallery 材质页一帧 19.6 ms，其中 **8.4 ms 是「玻璃税」** ——
> 而这笔钱里最大的一笔，是**为一颗 20×20 的把手拷了一整屏**。

上一轮把 GPU 占用的**测量口径**立起来了（见
[`2026-11-gpu-occupancy.md`](2026-11-gpu-occupancy.md)），这一轮用那个口径
去回答一个具体问题：**用玻璃到底要花多少钱，钱花在哪。**

---

## 一、钱花在哪（逐项掐掉测差值）

方法：在渲染路径上**临时**掐掉某一段，看 GPU 时间掉多少（本轮结束后临时代码已删除）。

| 场景 | ms/帧 | 说明 |
|---|---|---|
| 普通页（无滤镜） | 4.58 | 整窗重绘 + 呈现 + 全屏 MSAA 解析 |
| 玻璃页（材质 / 参考） | 19.59 | = 4.58 + **玻璃税 8.4** + 其它 6.6 |
| ├ 目标副本（`g_dst`） | **5.15** | 每个带滤镜的元素一次**整幅解析** |
| ├ 模糊乒乓（H/V） | **5.57** | 每趟 `2·3σ+1` 次采样 × 2 趟 × 7 个元素 |
| ├ 滤镜着色器 | 1.60 | 折射 / 透镜 / 磨砂 |
| └ 离屏机制（清屏 / 重画 / 合成 / 上传） | 2.69 | 与元素面积成正比 |

⇒ **74% 是「为小块元素做的全屏操作」。**
⇒ 而 D3D12 的整幅解析（`ResolveSubresource`）**只解析整个子资源** ——
MSAA 开着时那条路只能是整幅的（按区那条见 §九，第二轮补上了）。

---

## 二、根因：折射要读「背后」，背后要一份**全屏副本**

`Filter::Refraction` / `Lens` / `BackdropBlur` 都要采样元素**背后**的画面
（`g_dst`）。而背后在渲染目标里，**采样不了渲染目标** —— 只能拷一份。
⇒ 每个带滤镜的元素一次全屏拷贝。

**最荒唐的一笔**：开关的**玻璃把手**（20×20 px）也带滤镜 ⇒ 它也要拷一整屏。

---

## 三、SVG 的做法：不采样背景

SVG 的液态玻璃（`feDisplacementMap` + `feSpecularLighting`）里，
**位移图来自元素自己的形状**（alpha 的梯度），**背景不参与**：

```xml
<filter id="glass">
  <feGaussianBlur in="SourceAlpha" stdDeviation="2" result="bump"/>
  <feSpecularLighting in="bump" ... result="spec"/>
  <feComposite in="SourceGraphic" in2="spec" operator="arithmetic" .../>
  <feDisplacementMap in="…" in2="SourceAlpha" scale="70" .../>
</filter>
```

⇒ **不需要背景副本** ⇒ 不需要离屏 pass ⇒ 不需要全屏拷贝。
⇒ 整块玻璃只是**主趟里的一个四边形**。

**⇒ 照着做**：新增 `Filter::PixelOffset { amount, bezel }` ——
形状的边被**向内**推开（`amount` 像素，`bezel` 宽的带内过渡），
边上加一道法线方向的高光。位移是**解析**的（`sd_round_rect` 再求一次），
所以一个四边形就够。

### 实现在哪几层

| 层 | 改动 |
|---|---|
| `zephyra-core/src/filter.rs` | 新增 `Filter::PixelOffset`；`Material::Glass` 改用它；新增 `Material::GlassRefract`（**旧算法原样保留**） |
| `zephyra-fx/src/quad.rs` | 新增 `kind::GLASS`；`Vertex::from_rect_glass` 把两个参数放进 `uv`（圆角矩形的 `uv` 本来空着 ⇒ **不占新的顶点通道**）；展开时链**恰好**只有 `PixelOffset` ⇒ 画成玻璃四边形 |
| `zephyra-fx/src/offscreen.rs` | `plan_pass` 对纯 `PixelOffset` 链**不开离屏** |
| `zephyra.hlsl`（D3D11 / D3D12 逐字节相同的一份） | `PSMain` 里加 `kind == 5` 分支 |

⇒ **三个后端一行都不用改**：顶点布局没变、离屏管线没变、着色器是共享的那一份。

## 四、顺带修掉的两处真浪费

### 4.1 `PSBackdropBlur`：625 圈循环里 456 圈是空转

```hlsl
for (int ky = -12; ky <= 12; ++ky) {      // ← 写死
    float fy = float(ky) * stride;
    if (abs(fy) > r) { continue; }        // ← 绝大多数圈走这里
```

⇒ 着色器里的循环是**串行**的，这 625 圈的开销全记在每个片元头上，
而真正用到的采样只有约 169 次。

改成按**实际要采的点数**算上界（`taps = ceil(r / stride)` ⇒ `taps*stride == r`，
恰好覆盖原来 `|f| ≤ r` 的全部偏移）⇒ **采到的纹素一个不差** ⇒ 画面逐像素相同。

### 4.2 超椭圆 SDF：每片元 3 次 `pow`

```hlsl
corner_d = r * pow(pow(ax, n) + pow(ay, n), 1.0 / n);
```

`n` 是**运行期变量**（`shape_k` 从顶点插值出来）⇒ 编译器**没法**把它折成乘法链
⇒ 每个片元付 **3 次完整的 `pow`**（每次 ≈ log2 + exp2 + 一次乘）。

而样式表里有 **139 处** `corner-shape: superellipse(1.5)`（`n = 3`）——
**几乎每个面板、每个按钮的每个片元**都在付这 3 次 `pow`。

改成：`n` 取整时用乘法链 + 一次开根（`n=3` → `x*x*x` 与 `pow(x, 1/3)`）。
⚠ `cbrt` 在 `ps_5_0` 里**不存在** ⇒ 根仍用 `pow` —— 但**只一次**。

**A/B 实测（同一台机器、同一场景）：**

| | 全部 9 页 | 普通页 |
|---|---|---|
| 只有 4.1 | 7.31% / 6.23 ms/帧 | 4.91% / 4.39 ms |
| 再加 4.2 | **6.33% / 5.49 ms/帧** | **4.73% / 4.15 ms** |

⇒ 超椭圆这一处单独值 **~12%**。

## 五、结果

| | 改前 | 改后 |
|---|---|---|
| `material: glass`（材质样片 / 玻璃按钮） | 一次全屏解析 | **不画离屏、不拷全屏** |
| 开关把手 / 滑块拇指的玻璃 | 同上 | 同上 |
| 玻璃页 GPU | 22.08% / 24.41% | **15.20% / 17.39%** |
| 全部 9 页 GPU | 9.89% / 20.63% | **6.33% / 12.47%** |
| 离屏趟数（材质页） | 7 | **3** |

**玻璃税：8.4 ms/帧 → 剩下的 3 趟是「真实液态玻璃演示页」的三块玻璃
（`material: glass-refract` 一类）—— 那是**物理折射本身的演示**，按要求保留。**

### 画面变化（逐像素比对）

- 普通页：**0 个像素有差异**；
- 材质页：**138 / 1,120,000 个像素有差异，最大通道差 3**（超椭圆 `pow` →
  乘法链的浮点重排，落在 8 bit 上偶发 ±1~3 级）。

### ⚠ 视觉上要说清楚的一件事

物理折射把**背景**掰弯；像素偏移掰的是**形状自己的边**，**背景不再被折射**。
⇒ 「透过去能看见被弯折的背景」这件事没了，换来的是「透过去能看见背景，但它是直的」。

⇒ **这是取舍，不是等价替换。** 真实液态玻璃那条路**完整保留**
（`material: glass-refract` / `Filter::Refraction` / `Filter::Lens`），
要就用它。

## 八、第二轮（2026-11-14）：照着 `E:\liquid-glass` 的 SVG 配方重写玻璃着色

第一轮的廉价玻璃只是「形状向内推 + 一圈细高光」。真机截图上是**一颗白块，
中间一条对角线亮痕**（玻璃按钮 / 胶囊按钮 / 下拉按钮全中）。用户的原话是
「你看这个里面的 svg 是怎么做的，不要乱搞了」。

### 8.1 配方（`E:\liquid-glass` 的 `index.css` + `index.html`）

| SVG 那层 | 值 | 着色器里的对应 |
|---|---|---|
| `.glassDiv::before { background-color: rgba(255,255,255,.06) }` | 玻璃**体** | `tint`（6% 白） |
| `inset 0 0 20px -5px rgba(255,255,255,.45)` | 内侧白辉光 | 高斯鼓包，峰值 0.42 |
| `generateSpecularMap`：贴边 `sqrt(1-(1-f)²)` × `|dot(n,light)|` | 高光 | 一条 1~2px 的贴边细线 |
| `box-shadow: 0 4px 24px rgba(0,0,0,.18)` | 外投影 | 宿主装饰（不在着色器里） |
| `feDisplacementMap` | 位移**背景** | 廉价路没有背景 ⇒ 位移落到**玻璃体自己的边**（`alpha_tint` 走 `d2`） |

### 8.2 两条根因（都是自己写出来的）

1. **空框**：`alpha` 用了**位移后**的 `d2` ⇒ 玻璃的轮廓跟着往里缩，而填充是
   全透明的 ⇒ 缩出来的环里什么都没有 ⇒ 按钮只剩一圈描边、中间是背景。
   ⇒ 轮廓必须由 `d` 定；位移只许动**着色**（tint 的边）。
2. **白块 + 对角线亮痕**：高光剖面写成
   `rim_p = smoothstep(-rim_w, 0.0, depth)` —— 这个式子对 `depth ≥ 0`
   **恒等于 1**，也就是**整个内部**都在画高光（0.5 × facing ≈ 0.4 白）；
   而 `facing = |dot(n, light)|` 的 `n` 在超椭圆上走有限差分，`sd_round_rect`
   内部那一支是 `max(q.x, q.y)`，它的**切换线正是那条对角线** ⇒ 法线在那里
   跳变 ⇒ 亮痕。
   ⇒ 改成 `1 - smoothstep(0, rim_w, depth)`（从边往里衰减）。

### 8.3 为什么宽度要随元素缩放

CSS 那条 `20px` 是**绝对像素**，而且那个数是给 300×200 的演示面板的。照搬到
一颗 37px 高的按钮上，20px 的辉光带把整颗按钮刷白（第一版实测就是这个）。
⇒ 带宽取 `clamp(短边 × 0.10 + 位移 × 0.8, 2, 24)` px：220×120 的玻璃块
约 21px（接近 CSS 的 20），37px 高的按钮约 7px。

### 8.4 逐像素剖面（改后，参考页 `act:glass` 50×36）

```text
y=356..357  96, 151   ← 元素外 / AA
y=358       224       ← 高光细线（|dot| 加权的贴边亮线）
y=359..366  184→116   ← 内侧白辉光，指数式衰减
y=367..383  114       ← 玻璃体：96 底 + 6% 白（tint）
y=384..393  120→224   ← 对称的另一侧
```

整条剖面**左右上下对称**、中间是「底 + 6%」、边上一条亮线 + 一条软辉光 ——
这正是 SVG 配方在一条直线边上的形状。

## 九、D3D12 **有**按区解析：`ResolveSubresourceRegion`

第一轮（以及 `2026-10-gallery-stale-text-and-msaa-backdrop.md`）的结论是
「D3D12 没有按区解析」。**那条结论只对 `ResolveSubresource` 成立**：
按区版本在 `ID3D12GraphicsCommandList1` 上，带源 `RECT` + 目标偏移。

上一轮那次尝试失败的真正原因是**资源状态**（那条 dev-log 自己也写了：
「换回 5 参 `ResolveSubresource` 配同一个错状态也照样失败」）——
状态修好之后按区版本一次就通。

### 实现要点（都写在 `refresh_dst_copy` 的注释里）

- **区域记账**：副本可能只解析了一部分，所以 `DstCopy` 记 `resolved`；
  复用判据要求「已有区域 ⊇ 本次请求」。
- **只在小区域上走**：面积 ≥ 全幅 40% 时退回整幅（省不下什么，少走一条路径）。
- **矩形向外扩到偶数**：解析矩形落在 2×2 样本栅格上更稳；错位一律
  `E_INVALIDARG`，而那个错误要到 `Close()` 才现形（后果是画面永久冻结）。
- **四周再放 4px**：合成趟的双线性采样在边界外读半像素，只按包围盒解析时
  那半像素是上一次的内容（实测差 ≤7/255）。
- **`Close()` 真机验证**：跑 300+ 帧、切页、开关玻璃模式，stderr 无
  `0x80070057`；按区与整幅两条路的截图逐像素比对，裁切区外**完全一致**。

实测（gallery 1400×800 / MSAA 4× / UHD 630 / 材质页）：

| | 整幅解析 | 按区解析 |
|---|---|---|
| 材质页 | 8.08 ms | **7.14 ms** |
| 参考页 | 4.66 ms | **3.56 ms** |

参考页降得更多（那一页的滤镜元素都小，整幅解析的固定成本占比更高）。

## 十、投影外扩 4σ → 2.5σ

`OuterShadow::outset` 原来是 `radius * 4`，而 `radius` 就是高斯 σ。
2.5σ 处高斯值 1.2%，乘上投影色 alpha（玻璃档 0.1）＝ 0.12% —— 8 位通道上
0.3 级，看不见。

一块 220×120 的玻璃（σ=24）因此从 **412×312** 缩到 **364×264**（RT 面积
−25%）。材质页三块玻璃的装饰趟 2.04 → 1.6 ms。

⚠ 外扩**只影响离屏 RT 的尺寸**，不影响投影本身（投影还是按 σ 模糊）。

## 十一、玻璃装饰默认关

改完着色器之后，`Decorations::glass()` 那三层（24dp 外投影 + 高光 + 内阴影）
与着色器自己画的边缘**重复**了。逐像素实测：玻璃块区域平均差 **1.2/255**、
最大 22（只有边缘一圈）。

而它是**每块玻璃一趟离屏 RT**（投影 σ=24 ⇒ 外扩 2.5σ ⇒ 340×240，
元素本身才 220×120）。三块合计 **1.6 ms/帧**。

⇒ 开关（标签「装饰」）留着，**默认关**。想对比旧观感点开即可 ——
门禁 `the_glass_decor_toggle_flips_the_panes_decorations` 两个方向都钉住。

## 十二、最终数字（2026-11-14，gallery 1400×800 / MSAA 4× / DComp / UHD 630）

单页 = 2 × 平均值 − state 页。

|---|---|---|---|

## 七、留给下一个人的三件事

1. ~~**≤5% 在玻璃页上仍然够不着** —— 那一页**光内容本身**就要 5.2 ms/帧~~ ⇒
   **第二轮已经够着了**（材质页 4.60 ms / 4.9%），靠三件事：按区解析（§九）、
   投影外扩 4σ→2.5σ（§十）、玻璃装饰默认关（§十一）。
   ⚠ 这三件都不是「玻璃算法」的功劳 —— 玻璃本身已经是主趟里一个四边形了。
2. **玻璃的「模糊乒乓」还在 5.6 ms 那一档的量级** —— 现在靠步长抽稀压下来了，
   但那一步改的是**核的采样密度**（无偏、方差略大）。若要更稳，
   正路是**可分离模糊 + 双线性采样**（9 个采样 ≈ 17 个纹素），那要重写着色器。
3. **「同帧内多个带滤镜元素共享一份副本」还没做** —— 现在每个元素各拷一次
   （按区解析之后每次只拷自己的区域，代价已经小了一个数量级，但语义上仍是
   「每个元素一份」）。**注意**：副本本身只有一份（`DST_SRV_SLOT`），共享的是
   *内容* 而不是 *资源*，两者的区别在 `DstCopy::resolved` 那段注释里。
